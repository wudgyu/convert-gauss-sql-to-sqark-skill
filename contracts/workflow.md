# 工作流契约

本文件定义 gauss2spark 工作流的节点、交接方式与放行规则。六个 skill 都以此为准；
与任何 skill 的正文冲突时，以本文件为准。

## 范围

| 项 | 值 |
|---|---|
| 源方言 | openGauss，`DBCOMPATIBILITY = PG` |
| 目标方言 | Spark SQL 4.2.0（唯一测试覆盖版本） |
| 转换主体 | 由模型按规则库完成，确定性工具只负责切分、校验、产物组装 |
| 明确不支持 | PL 块（DO / FUNCTION / PROCEDURE / TRIGGER）、psql 元命令 |

## 节点与顺序

```
analyze → convert → review → fix ─┐
                        ↑          │
                        └──────────┘  最多 2 轮
                                   ↓
                                gate → 最终 SQL / 过程文档 / 审计报告
```

| 节点 | Skill | 职责 | 不改动什么 |
|---|---|---|---|
| 编排 | `gauss2spark` | 建 run 目录、驱动节点、执行闸门、组装产物 | 不参与转换判断 |
| 分析 | `gauss2spark-analyze` | 切分、分类、风险分级、确定适用规则 | 不改写任何 SQL |
| 转换 | `gauss2spark-convert` | 按规则库改写，逐句记录决策与证据 | 不新增规则 |
| 审核 | `gauss2spark-review` | 独立复核语义、扫描残留方言、套用漂移清单 | 不修改转换结果 |
| 纠错 | `gauss2spark-fix` | 按 findings 修复，最多 2 轮 | 不覆盖审核结论 |
| 规则 | `gauss2spark-rules` | 规则库增删改查与校验 | 不参与单次转换 |

## 仓库定位

所有节点都需要仓库根目录（即同时含 `tools/bin/g2s-core.jar` 与 `rules/` 的目录）。
按以下顺序解析，取第一个命中：

1. 环境变量 `G2S_HOME`
2. 从本 skill 所在目录逐级向上查找含 `tools/bin/g2s-core.jar` 的目录
3. 从当前工作目录逐级向上做同样的查找

工具入口为仓库根下的 `./g2s`（bash 包装脚本）。若 jar 不存在，先运行
`tools/build.sh` 构建；构建失败则中止并报告，不要绕过工具继续。

**引用解析规则**：skill 正文里的 `contracts/`、`rules/`、`checklist/`、`tools/`
等路径一律相对**仓库根**解析，不要相对 skill 文件所在位置解析。
写作时为了在人读时直观，用了 `../../contracts/...` 这类相对写法；
但 skill 被安装到别的目录（例如某个 CLI 的全局 skill 目录）时，相对写法会失效，
此时必须用仓库根或 `G2S_HOME` 重新定位。工作流要求六个 skill 与仓库一并可用，
不支持把单个 skill 单独拷走使用。

## 大文件路由

`g2s split` 同时给出路由判定：

| 条件 | 路由 | 处理方式 |
|---|---|---|
| 行数 ≤ 200 且语句数 ≤ 20 | `direct` | 整个文件直接交给模型，不强制分片 |
| 行数 > 200 或语句数 > 20 | `split` | 按语句分片处理，逐条记录 |

两种路由都必须产出 `statements.jsonl` 与逐语句记录，否则无法追溯。

## 档位与放行

每条语句在分析阶段被定为一档，档位定义见 `rules/index.yaml`：

| 档位 | 含义 | 闸门行为 |
|---|---|---|
| `auto` | 确定性转换、低风险 | 自动放行 |
| `confirm` | 可转换但语义有偏差或依赖前置条件 | 阻断，需人工确认 |
| `blocked` | 无法转换 | 阻断，必须人工改写 |

闸门规则：

1. 只有 `auto` 自动放行。
2. 任一 `confirm` 或 `blocked` 语句没有对应的审批记录时，**不产出最终 SQL**，
   退出码非零，并输出阻断清单。
3. 人工确认有三种处置：接受转换结果、提供人工 SQL、或排除该语句。
   人工补写的 SQL 同样进入最终文件，并在审计报告中标记来源为人工。
4. 只有显式传入 `--allow-partial` 才产出残缺版本，且必须带显著提示头。

## 人工确认是纠错的正规路径

如果 `checklist/spark-4.2.0-baseline.md` 或规则库能直接判定某条语句无法转换，
就把它列入阻断清单，**不要猜测改写**。

当同一构造在多个语句中重复出现时（真实语料中 `DEFAULT nextval(...)` 就是典型），
应当按构造一次性确认策略后批量放行，而不是逐条询问。

## 保真度声明

每次运行都必须记录本次采用的校验档位，并在审计报告中如实声明：

| 档位 | 含义 |
|---|---|
| `static-only` | 仅结构检查与方言扫描 |
| `syntax-parse` | 已用 Spark 4.2.0 解析器验证语法 |
| `explain-checked` | 已对转换结果执行 EXPLAIN 校验（需要 schema） |
| `execution-verified` | 已在真实环境执行并比对结果 |

未达到 `execution-verified` 时，报告必须写明「结果未经真实数据执行验证」。
